# B0043 · Ramping up on an unfamiliar codebase

| Section | Topic | Difficulty |
|---|---|---|

## Question

Tell me about a time you had to become productive quickly in a large, unfamiliar codebase.

## Answer

- Run it locally and read the architecture docs and ADRs.
- Trace one request end to end with a debugger or logs.
- Read the tests to learn intended behaviour; map the key modules.
- Pick a small bug fix to learn the build and deployment pipeline.
- Ask owners targeted questions; use git history to understand intent.
- Write down what you learn and improve the onboarding docs.
- Use code search and AI assistants carefully, verifying what they tell you.

Result to quote: first PR in week one, owning a component by month two.

## Likely follow-ups

- How do you decide what not to learn yet?
- How do you avoid breaking things you don't fully understand?
