# B0091 · Two teams want conflicting platform changes

| Section | Topic | Difficulty |
|---|---|---|

## Question

Two client teams want conflicting changes to a shared platform API. How do you resolve it?

## Answer

- Understand each need as a problem rather than a solution, with its impact, urgency and usage data.
- Look for a design that serves both: configuration options, versioned endpoints, extension points, per-tenant feature flags.
- If a trade-off is unavoidable, make it explicit against criteria (firm priorities, users affected, risk) and have the product owner and leads decide.
- Communicate the decision, rationale and timeline to both teams, and offer the deprioritised team a workaround.
- Protect platform coherence by avoiding one-off hacks.

## Likely follow-ups
